# 설치·업데이트·원복 (Windows10/11 x64)

**원래 Ultimate Bluetooth Controller의 본체 라벨80NA와 원래 동봉 수신기만 대상입니다.**
신형 Ultimate2/2C, 비슷한 이름의 Ultimate2.4G 모델은 다른 장치입니다.
현재 공식 컨트롤러1.11, 수신기1.04인지 제조사 도구에서 먼저 확인하세요.
다른 버전은 먼저 제조사 도구로 이 공식 버전을 설치합니다. 제품이 다르면 중단하세요.

## 준비

v0.1.2 이상을 사용하세요. 초기0.1.0/0.1.1 준비 도구는 공식 updater의 `data` 폴더를 누락해 장치 연결 시 쓰기 전에 종료될 수 있었습니다.
새 버전은 `Update.cmd`에서 매번 준비·복구하고 DLL 로드 전 누락 검사도 합니다. 기존 cache는 그대로 사용할 수 있습니다.

1. 충분히 충전한 패드, 검증된 USB 데이터 케이블, PC의 안정된 USB 포트를 준비합니다.
2. 릴리스의 Windows ZIP 전체를 짧은 경로에 풉니다. ZIP 안에서 실행하지 마세요.
3. 릴리스 SHA256SUMS와 파일 해시를 대조합니다. PowerShell 예: `Get-FileHash .\PatchTool.exe -Algorithm SHA256`.
4. `Create-Firmware.cmd`를 실행합니다. 공식 원본 두 개와 updater ZIP을 내려받아 고정 SHA-256을 확인합니다.
5. 성공하면 `output`에 수정본4개와 공식 원복2개, SHA256SUMS가 생깁니다.
   `cache`에는 받은 공식 원본, `vendor-runtime`에는 수정 없는 제조사 프로그램이 생깁니다.

릴리스 실행 파일은 이 프로젝트에서 만든 서명 없는 프로그램입니다. 출처와 해시를 확인하고 실행 여부를 판단하세요.
최초 다운로드에는 인터넷이 필요합니다. 원본 firmware 서버는 HTTP이므로 고정 해시를 반드시 확인하며,
프로그램에 검사를 끄는 옵션은 없습니다. 공식 파일이 바뀌면 자동으로 새 버전에 패치를 추측해 적용하지 않습니다.

소스만 받은 경우 Python3.10+에서 `python patcher.py prepare`로 생성할 수 있습니다.
`Update.cmd`/`FlashTool.exe`는 Windows 릴리스 또는 [빌드](../windows/build.ps1)로 만든 실행 파일을 사용합니다.
Linux/macOS의 패치 생성은 가능하지만 이 배포의 실제 쓰기 도구는 Windows용입니다.

## 컨트롤러 한 대 업데이트

1. 다른 패드·수신기·8BitDo USB 장치를 **모두 분리**합니다. 도크를 통한 연결 대신 패드 USB-C를 PC에 직접 연결합니다.
2. Ultimate Software와 제조사 updater를 종료합니다. 뒤 스위치는2.4G로 둡니다.
3. 패드 USB를 빼고 Home을 충분히 길게 눌러 전원을 완전히 끕니다.
   위쪽 **L/R 범퍼**를 동시에 누른 채 USB를 꽂아 ROM 업데이트 모드로 들어갑니다.
   정상 앱/배터리 전원이 계속 켜져 있으면 케이블만 바꿔 꽂아서는 진입하지 않을 수 있습니다.
4. `Update.cmd` 실행 후 선택합니다.
   - **1**: 최초 ADC+배터리 경고만 수정하는 보수적 변형.
   - **2**: 최종 enhanced. ADC+배터리+2ms+일정+스틱 활동 수정.
5. 정확한 모델 확인에 `80NA`를 입력합니다. 모델 읽기와 이미지/제조사 DLL 해시 검사가 끝나면 `FLASH`를 입력합니다.
   진행 중 케이블을 빼지 마세요. 장치가 없거나 여러 대, 모델/버전/CRC 불일치이면 쓰기 전에 중단합니다.
6. `Transfer100%, no error callback`을 확인한 뒤 USB를 빼고 버튼을 누르지 않고 다시 꽂습니다.
   필요하면 Home으로 완전히 끈 다음 일반 연결합니다.
7. 방향키·ABXY·스틱·트리거·진동·충전·대기/복귀를 확인합니다.

도구는 이미지 버전을111로 유지합니다. 화면의1.11만으로 수정본 설치를 구별할 수 없습니다.
진행100%는 전송 완료 판단이며 앱 전체 readback이나 기능/장시간 안정성을 대신하지 않습니다.
공개 도구에는 임의 이미지·PID 강제 맞춤·모델 검사 생략 기능이 없습니다.

## 수신기 한 개 업데이트

1. 컨트롤러 USB와 다른 수신기를 빼고 **원래 동봉 수신기 한 개만 PC에 직접** 꽂습니다.
   짝인 패드도 잠시 꺼 수신기가 대기 모드에 있도록 합니다.
2. 먼저 `vendor-runtime`에서 제조사 프로그램을 실행해 **Ultimate BT Receiver1.04**임을 확인한 뒤 종료합니다.
   `2dc8:3109`는 대기, `6007`은 설정, `3208`은 ROM updater가 될 수 있습니다.6007만으로 모델을 판정하면 안 됩니다.
3. `Update.cmd`의 **3번**을 선택합니다. 도구는 확인된 대기/설정 인터페이스에서 제조사의 표준 부트 명령을 보냅니다.
4. ROM 응답의 펌웨어 모델6008과 선택 이미지6008을 확인한 뒤에만 쓰기를 시작합니다.
5. 완료 후 수신기를 다시 꽂고 패드를2.4G로 켭니다. 두 세트라면 한 세트씩 반복합니다.

공개 어댑터의 본체 기록 경로는 두 번째 컨트롤러에서 전체 재읽기와 입력까지 확인했습니다.
수신기 독립 identity preflight는 기존 개인용 어댑터에 추가한 읽기 검사이며,
이 새 포장으로 수신기를 실제 재플래시하는 시험까지 한 것은 아닙니다.
ROM 응답 형식이 예상과 다르면 **쓰기 전에 멈추는 것이 정상**입니다. 검사를 제거하거나 다른 기종 파일을 쓰지 마세요.
원래 실제 기록에 성공한 경로는 동일한 제조사 DLL의 로컬 파일 API였습니다.

## 원복·인식 실패

- 프로그램이 정상 열리면 `Update Manually → Ultimate BT → v1.11`,
  수신기는 `Ultimate BT Receiver → v1.04`를 선택해 공식 버전으로 되돌릴 수 있습니다.
  앱을 실행할 때 작업 폴더를 제조사 프로그램 폴더로 둡니다. 패키지는 이 위치에 DLL을 준비합니다.
- 이 도구의 **4번**은 컨트롤러 공식 원본, **5번**은 수신기 공식 원본입니다.
  생성된 `RESTORE-*.dat`는 공식 배포와 동일하며 사용자별 전체 플래시 백업은 아닙니다.
- 컨트롤러가 정상 인식되지 않으면 USB를 빼고 Home을 약8초 눌러 완전히 끈 뒤 L/R을 누른 채 다시 꽂아3208을 시도합니다.
  제조사 updater가 부트 장치를 인식하는지 확인하세요. 모든 하드웨어 고장이나 손상에서 복구된다는 보장은 없습니다.
- Windows가 장치 설명자 요청 실패를 보이면 그 상태에서 추가 쓰기를 시작하지 않습니다.
  케이블·직결 포트·완전 전원 종료를 확인합니다. 버전0 표시는 고정 버전 레코드를 확인하기 전까지 실제 버전으로 판단하지 않습니다.
- 원본/DLL의 해시가 다르다는 오류는 임의 다운로드로 우회하지 말고 [Issue](https://github.com/a77ila2000/8bitdo-Ultimate-Bluetooth-1th-/issues)를 남깁니다.
  모델·OS·선택 변형·오류 메시지는 도움이 되지만 일련번호·MAC·키·전체 개인 덤프는 올리지 마세요.

## 적용 후 확인할 것

최종 조합의500Hz와 기존 전원 꺼짐 해결은 미확인입니다. 먼저 짧게 한 세트의 실제 입력을 확인한 뒤
장시간 게임, 두 패드 동시1P/2P, 진동/터보/충전, 대기/복귀와 배터리 지속시간을 따로 확인하세요.
기존 증상이 재현되면 시간·연결 방식·표시등 상태·진동/충전 여부와 사용 변형을 기록하면 원인을 좁힐 수 있습니다.
Bluetooth 속도 개선을 목표로 한 펌웨어가 아닙니다.
